# Global final-authorization workflow

## Input.md requirements

1. Keep user requirements in `Input.md`; record functional implementation and evidence in the newest `.ai/changes/YYMMDDHHmm.md` record.
2. Before a final response, require a separate Agent to compare `Input.md` with the latest timestamped change record and permit final emission only with `final-authorized`.
3. When the reviewer returns `continue`, resume the first missing bounded task instead of ending the active contract.

## Implemented behavior

- Added the `completion-authorization` management Skill and its active copy. It defines the two required review inputs, requirement-to-evidence comparison, unresolved-step rejection, and the two permitted receipt statuses.
- Updated both global rule copies with a mandatory change-record format, independent-review invocation, `continue` handling, and a final-send ledger predicate requiring `final-authorized`.
- Added matching managed and active `completion-gate.json` policy settings that name the Skill, inputs, timestamp pattern, and receipt status; the global rule explicitly applies this setting and rejects missing, mismatched, or malformed settings as `continue`.

## Verification evidence

- Skill implementation was independently created and validated with the Skill Creator quick validator for both source and active copies.
- SHA-256 parity was verified for both rule copies, both settings copies, and both Skill copies.
- An independent Agent reviewed the source/active parity and final-send conditions. Its ambiguity finding about selecting one latest record was repaired in both rule copies; the repaired pair requires a single filename-ordered latest matching record.
- A second independent review found that the Skill did not consume the policy setting. The Skill was repaired to parse both managed/active settings, require byte parity, use the configured paths/pattern/status, and return `continue` for a settings defect; its active copy was synchronized before revalidation.
- A subsequent review found an unvalidated `reviewer_skill` and rule text that hardcoded configured values. The Skill now rejects a reviewer-skill mismatch, and both global rule copies use the setting fields—including the ledger receipt status—rather than fixed policy literals.
