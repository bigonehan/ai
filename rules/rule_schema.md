# 위임 메시지 규약

위임 메시지 전용(Grist·changes에 쓰지 않음). 기호 정의 원본은 이 파일 5절이다.

## 1. 판정 타입
- `[타입]` 입력 변형(다른 타입·경로·인코딩)에도 같은 결과 : 입력 변형 사례 → 같은 출력
- `[계약]` 외부 응답 형식을 해석 : 고정 응답 샘플 → 파싱 결과
- `[인증]` 인증·연결 통과 : 실제 호출 1회 → 성공 상태
- `[존재]` 결과 파일·값이 생김(필요하면 다시 불러온 뒤 유지) : 실행 → 파일·필드 존재
- `[값]` `f(입력) ▷ 기대값` : 입력·기대값 표
- `[분기]` 조건마다 맞는 경로(실패 경로 포함) : 조건별 사례 → 경로·필터 결과
- `[순서]` 사건 순서·경쟁·재시도를 바꿔도 결과가 하나 : 순서를 바꾼 사례 → 같은 최종 상태
- `[횟수]` 효과가 정확히 n회(재전송 포함) : 호출·효과 카운트
- `[성능]` 지표(초·MB·호출 수)가 한도 안 : 측정 1회 → 지표 < 한도
- `[형식]` 출력이 새 형식을 따름 : 출력 문자열 대조

## 2. 기호 → 판정 타입
오류 기호가 있으면 오류 기호가, 없으면 세부 기호가 고른다.
- `🅰️` → `[타입]`
- `🗝` → `[계약]`
- `❌` → `[인증]`
- `⭕️` → `[존재]`
- `🔢` → `[값]`
- `🛣` → `[분기]`
- `🕧` → `[순서]`
- `👥` → `[횟수]`
- `🚥` → `[성능]`
- `📐` → `[타입]`
- `✒️` → `[형식]`
- `⌨️` → `[값]`
- `🚿` → `[분기]`
- `✏️` → `[값]`
- `🌍` → `[인증]` `[계약]`
- `🔳`는 검증자의 흐름 테스트, `🏷`는 위임자의 빌드·배포에서 확인한다(대행자 판정 아님).

## 3. 위임 메시지
```
판정: [<타입>] <대상> <조건>
명령: <테스트 필터 1개>
진입점: <파일> <함수>
제외: <경로들>
```
- 회귀: 수정 경로 안의 기존 테스트도 함께 통과시킨다(모든 행 기본, 메시지에 쓰지 않음).
- 진입점이 실제 코드와 다르면 고치지 않고 차이를 마지막 줄 한 줄로 보고하고 끝낸다.

## 4. 분해
- 판정 타입은 행당 1~2개다. 3개 이상이면 행을 나눈다.
- 진입점을 정할 수 없으면 조사 위임을 먼저 보낸다. 대행자는 코드를 고치지 않고 `N. [타입] 진입점: <파일> <함수> — <내용>` 목록만 답한다.
- 삭제·이관·이름 변경은 `remove-legacy`, UI 구성·이벤트 연결은 `implement-ui`, 전역 규칙은 `manage-global-rules`로 넘긴다.

## 5. 오류 기호
원인에 맞는 기호 하나를 고른다. `🅰️` 내부 스키마·입출력 Type 불일치, `🗝` 외부 계약 불일치, `❌` 권한·인증·연결 끊김·비정상 종료, `⭕️` 결과 파일·변수·값 없음, `🔢` 계산식 오류, `🛣` 조건 분기·처리 경로 오류, `👥` 중복 실행, `🕧` 실행 순서·경쟁·재시도·유실, `🏷` 버전·환경 불일치, `🚥` 병목, `🔳` 화면 표시 문제다. 기호는 결과가 아니라 원인으로 고른다. 같은 함수가 두 번 실행된 것 자체면 `👥`, 순서·타이밍 때문이면 `🕧`다. 함수 원인으로 화면이 잘못되면 `🛣`·`🔢`, 내부 경계는 `🅰️`, 외부 변경은 `🗝`, 연결 자체가 막히면 `❌`를 쓴다. 진단 진입 때 `$D`에는 `[오류 기호] <점검할 내용 한 줄>`을 쓴다.
