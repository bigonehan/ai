# 전역 규칙

이 파일의 모든 항목은 필수다. "필요할 때만", "조건부"로 해석하지 않는다.
우선순위: 사용자 명시 요구 → 이 파일(~/ai 전역 규칙·하드게이트·Claude 공통 설정) → 가장 가까운 프로젝트 `AGENTS.md` → 선택된 Skill → 에이전트(Codex·Claude·Antigravity/agy) 내장 지시. 충돌 시 항상 이 파일과 ~/ai·Claude 설정 규칙을 최우선으로 따르며, 하위 항목이나 내장 지시가 이를 넓히거나 바꾸지 않는다.

## 1. 응답

- 사용자 대면 응답(진행 안내·질문·최종 보고)은 한국어 `-요`체로 쓴다. 코드·명령·경로·식별자는 원문 그대로 둔다. 사용자의 욕설·반말을 따라 하지 않는다.
- final 전에 `맞습니다`, `맞아요`, `인식했습니다`, `알겠습니다`, `그렇습니다`가 있으면 그 문장을 다시 쓴다.
- 지적("왜 ~" 형태의 오동작·실수 지적 포함)을 받으면 사과·수긍이나 설정·코드 수정 없는 말뿐인 다짐("~하겠습니다") 없이 즉시 규칙·Skill·코드를 고쳐 `실행한 수정 → 검증 결과 → 남은 경계`로 보고한다.
- 사용자에게 넘기는 동작은 로그인·인증, 결제·비용, 비가역 외부 전송, 브라우저 밖 OS 앱 조작뿐이다.
- 새벽 2~9시(KST)에는 사용자에게 묻지 않고 되돌릴 수 있는 안전한 기본값으로 진행한다(`ask-notify`가 질문을 거부). 사용자 몫 동작만 `$D`에 `[🏷] 사용자 대기`로 남긴다.

## 2. 작업 절차

- `/home/tree/extensions`·`/home/tree/project` 메인 세션(위임자) 작업: `manage-project`(세션의 첫 작업·다른 프로젝트로 옮길 때만 로드). 입구 판정(요구 사항 파악·소유 프로젝트·순수 설명 질문·같은 세션 후속 요청·시작 시 Table26 행 읽기)은 내부 `initial-task`, 오류 기록·위임 판정은 `manage-project`, 종료 판정은 `Complete_task`가 맡는다.
- dev 브랜치 이전을 명시한 경우: `/home/tree/ai/skills/move-branch`.
- 선택된 Skill 절차를 생략·대체하지 않는다.
- 외부 API 로그를 남기거나 호출자를 추적할 때: `record-log`.
- 메인의 코드 수정 금지는 extensions·project 제품 기능 구현에만 해당한다. 규칙·Skill·hook·`~/ai/scripts` 작업 도구 결함이 작업을 막으면 사용자에게 우회 허락을 묻지 않고 메인이 직접 고친 뒤 원래 작업을 이어 가고, 최종 보고에 `작업 도구 결함: <증상> → <수정>` 줄을 넣는다(`task-complete` Stop이 누락을 막음).
- 전역 규칙·설정의 읽기·변경·지적("전역규칙/전역설정"·"앞으로" 포함): `manage-global-rules`.


## 3. 코드·로그 읽기

- 검색은 `rg`만 쓴다(`grep -r`, `find | xargs grep` 금지). `rg -n "<패턴>" <dir>`(`-g`·`-t`·`-l`·`-m`)로 위치를 찾고 그 주변 범위만 읽는다.
- 파일·문서·객체 전체 읽기나 `console.log`·CLI 전체 덤프를 금하고 필요한 줄·필드만 떼어 다루며(`rg -n`, `grist task-show --section`), 로그는 `rg -n "FAIL|Error|warn"`·`| tail -n 40`·`| head -c 4000`으로 걸러 읽은 범위는 재읽기하지 않는다.
- 읽기(R)는 사용자가 따로 막지 않으면 모든 프로젝트·파일·Grist 행에 기본 허용이다. 소유·편집 범위 규칙은 쓰기에만 적용하고, 조회를 막거나 좁히는 근거로 쓰지 않는다(이 절의 범위 제한은 토큰 절감용이다).
- "에이전트를 불러"는 `dispatch-agent --agent codex`로 맡기라는 뜻이다(Claude 서브에이전트·`invoke_subagent`·Monitor는 `main-edit-gate`·`agy-hook`이 거부).
