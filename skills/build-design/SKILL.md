# 기본 
- yes/no 또는 confirm/cancel 성격의 모든 UI는 기본 순서를 `확인/시작/적용/삭제` 왼쪽, `취소/닫기` 오른쪽으로 통일한다. 기존 구현마다 순서가 섞여 있으면 같은 턴에 전수 점검 후 함께 바로잡는다.
- 버튼이 같은 pane/action 영역에서 함께 보일 때는 크기, radius, padding, 아이콘 크기를 통일한다. 일부만 원형 아이콘 버튼이거나 기본 브라우저 버튼처럼 튀면 같은 턴에 공통 버튼 규칙으로 바로 맞춘다.
- `확인`과 `취소`가 함께 나오는 경우 DOM 순서와 시각 순서를 모두 `확인 -> 취소`로 고정한다. flex 정렬로 시각만 바꾸지 말고 실제 마크업 순서도 같이 맞춘다.
- 저장/닫기/확인/취소 계열 버튼은 pane 내부 헤더나 본문 끝이 아니라, 해당 화면 또는 dialog의 pane 바깥 하단 우측 footer action 영역에 둔다.
- 기존 디자인 시스템이 있으면 그 토큰과 컴포넌트 체계를 우선 사용한다. 별도 색상/다크테마/버튼 체계를 새로 들이밀지 않는다.
- 기존 핸들러, modal, 액션 버튼이 이미 존재해도 그걸로 구현 완료로 간주하지 않는다. 렌더된 화면에서 요청한 노출/배치/동작이 맞아야 한다.
- 완료 판정 최소 기준은 화면 렌더 결과 기준이다: 메인 버튼/액션의 순서, 노출 여부, disabled 조건, 클릭 후 modal 종류, 저장 후 파일/상태 반영이 사용자 요구와 일치해야 한다.
- `구현했다`, `이미 있다`, `완료됐다`라고 답하기 전에는 실제 렌더 화면 또는 UI 자동화에서 위 항목을 직접 확인해야 한다.
- UI 관련 검증은 기존 테스트 통과만으로 충분하지 않다. 사용자 요구를 직접 검증하는 assertion이 없으면 테스트를 먼저 추가/수정한 뒤 구현 완료를 선언한다.
- UI 기본 점검 하드게이트는 아래 5개를 항상 포함한다.
  - `item이 wrapper 밖으로 나오면 실패`
  - `checkbox가 item 왼쪽이 아니면 실패`
  - `편집/삭제가 icon이 아니면 실패`
  - `current.png 대비 group header / control / item의 상대 위치가 바뀌면 실패`
  - `텍스트 버튼이 남아 있으면 실패`
- 스크린샷이 주어진 경우 코드 구조보다 스크린샷의 실제 배치와 노출 상태를 우선 기준으로 삼는다.
- 스크린샷이 주어진 UI 작업은 자동화 테스트 외에 실제 스크린샷 캡처를 다시 수행하고 `이미지 확인`이 끝나기 전에는 완료 판정을 금지한다.
- 스크린샷 기반 UI 검증에서는 `스크린샷 재현 경로`, `캡처 파일`, `post-change screenshot`, `이미지 확인`, `배치 차이`를 작업 중 문서에 남겨야 한다.
- 스크린샷이 `current.png`로 지시된 경우, 그 이미지는 참고 예시가 아니라 목표 배치 계약으로 취급한다.
- `current.png` 기반 UI 작업은 구현 전에 반드시 아래 4가지를 문서에 고정한다.
  - `유지해야 하는 기존 요소`
  - `추가해야 하는 새 요소`
  - `삭제가 명시된 요소`
  - `금지된 재배치`
- `current.png`에서 보인 에셋의 상대적 위치는 반드시 유지한다.
  - 상하 관계: `A 아래 B`
  - 좌우 관계: `A 왼쪽/오른쪽에 B`
  - 포함 관계: `A 안에 B`
  - 동일 컨테이너 관계: 같은 카드/섹션/툴바 안에서 함께 보여야 하는 요소
  - 계층 관계: 헤더/툴바/리스트/item 순서와 소속
- 사용자가 삭제나 위치 변경을 명시하지 않았는데, `current.png`에서 보인 기존 요소의 상대 위치를 임의로 바꾸면 실패다.
- `current.png` 기반 작업에서는 assistant가 더 낫다고 판단한 재배치, 요소 축소, 컨테이너 분리, 전역 toolbar 이동을 금지한다.
- 스크린샷 기반 UI 작업은 완료 전에 다음 루프를 모두 끝내야 한다.
  - 스크린샷 기준 UI 경로 재현
  - 요청한 동작을 직접 검증하는 assertion 추가 또는 갱신
  - post-change screenshot 캡처
  - 이미지 확인
  - `배치 차이`와 `남은 차이 없음` 또는 잔여 차이 기록
- passing test만으로는 스크린샷 기반 UI 작업 완료 근거가 되지 않는다. post-change screenshot과 상대 위치 대조 결과가 반드시 함께 있어야 한다.
