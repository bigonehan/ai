# 기동 실패·중간 종료: exit 2·7, 로그 없음, 창 사라짐

아래 중 하나일 때 위임자가 읽는다.

- `exit=2`·`exit=5`의 `last=실패 — tmux 없음`: 호출 셸이 tmux 밖이고 실행 중인 tmux 서버도 없다.
- `exit=7 last=실패 — 기동 지연: <단계별 ms>`: pane 기동·첫 로그가 60초를 넘었다.
- 백그라운드로 띄운 뒤 30초 안에 `<dir>/.ai/dispatch/<id>.log`가 생기지 않았다(기동 실패).
- 대기 중 실행 창(`tmux list-windows`)이 사라졌는데 `.exit`가 없다(중단).

## 대응

- 완료 알림만 기다리지 않는다. 위 신호를 보면 그 자리에서 대기를 끝낸다.
- 기동 결과는 `| tail` 뒤 exit code가 아니라 출력의 오류 줄·`.exit`로 판정한다.
- exit 7은 소스 문제다. 재시도하지 않고 가장 느린 단계를 `$J` 원인으로 기록한다.
- 원인이 `dispatch-agent` 등 작업 도구 결함이면 사용자에게 우회 허락을 묻지 않고 위임자가 직접 고쳐 다시 띄운다. tmux 서버 기동·로그인처럼 사용자 몫(전역 규칙 §1)일 때만 보고한다.
- `tmux new-window`로 우회하지 않는다(261031 `TMUX is not set` 실패가 파이프 exit 0에 가려지고, `$?`가 든 명령 문자열이 fish 문법 오류로 즉시 닫힌 창을 `.done`만 기다리며 20분 넘게 보고하지 않음).
