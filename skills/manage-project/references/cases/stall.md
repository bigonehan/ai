# 응답없음: exit 4 (stall)

`dispatch-agent`가 `exit=4 last=실패 — stall: <줄>`(또는 검증자 `실패 — <행> [🚥] 검증 정체: stall: …`)로 끝났을 때 위임자가 읽는다. 대기 중 감시 로그(`<project>/.ai/logs/*.log` + `--watch-log`)에 같은 `ack=rejected` 줄이 2번 연속이거나, 검증자의 새 `[verify-step]` 줄이 120초 동안 없거나, 대행자 실행 5분 이후 5분 동안 새 줄이 없어 에이전트를 멈춘 경우다.

- `last`의 `<줄>`이 병목 경계다. 같은 정체가 2회 연속이면 `dispatch-agent`가 `$D="[🏷] 사용자 대기"`를 기록하고 추가 재개를 막으므로 사용자에게 보고한다. 1회째면 `$I`·`$J`·`$H=진단`을 기록하고 같은 흐름 대행자에게 `--continue`로 넘긴다. 같은 프롬프트로 바로 다시 띄우지 않는다.
- 원인을 더 알아야 하면 `grist task <id>`의 `$I`·`$J`를 먼저 보고, 비어 있을 때만 `--continue`로 "`$J`에 원인을 기록하고 끝내라"고 맡긴다. 위임 로그·pane은 읽지 않는다(`main-edit-gate`가 거부).
- 검증·API 탐색이 5분을 넘는 병목은 타임아웃을 늘려 덮지 않고, 중간 로깅으로 경계를 찾아 소스를 고치도록 위임한다.
- 자동 분석 검증자(`resolve-deadlock` `--analysis`) 연쇄를 띄우지 않는다.
