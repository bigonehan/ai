# 지연: exit 6 (5분 판단 지점)

`dispatch-agent`가 `exit=6 last=진행 — <행>: 경과 <분>m, 로그 +<바이트>B/5m, H=<$H>, 감시 <줄>`로 끝났을 때 위임자가 읽는다. 대행자가 기대 시간(`--expect-seconds`, 없으면 5분)을 넘겨 실행 중이며 pane은 남아 있다(일반 검증자는 5분에 강제 종료되어 `[🚥]`로 끝난다). 위임자는 그 한 줄로 아래 넷 중 하나를 정하고, 기다리기만 하지 않는다.

- **기대 초과**(`기대 <N>s 초과` 표시, 또는 짧은 CLI 확인이 1분 넘음): 계속 대기를 고르지 않는다. 바로 `--continue`로 "`$J`에 지금 막힌 단계와 마지막 record-log 줄을 기록하고 끝내라"를 맡기거나, 위임자가 그 경계의 호출을 직접 시간 측정(`date +%s%3N` 전후)해 원인을 찾는다.
- **계속 대기**: 요약의 로그 tail이 실제로 바뀌었고(`새 줄 <n>` n>0, 마지막 고유 줄이 다음 단계로 진행) `반복 <줄> ×<n>`·`내용 정체`가 없으며 `H`가 기대 단계로 가는 중일 때만 → `dispatch-agent --attach --project <dir> --row <id> --decision "<근거: 새 줄 수·마지막 고유 줄·H>"`를 백그라운드로 다시 실행한다(`--decision` 없으면 거부, 사유는 `$D`에 남는다). 로그 용량 증가(`+<n>B`)만으로는 계속 대기를 고르지 않는다(같은 404 반복도 용량은 늘어남). Claude Bash 백그라운드 명령은 600초에 끊기므로 한 번의 대기는 540초를 넘기지 않는다.
- **방향 재지시**: 로그는 늘지만 `H`가 그대로이거나 감시 줄이 요구 밖 경로·같은 실패 반복을 보일 때 → 대행자 종료를 기다리지 않고 `$I`·`$J`를 기록한 뒤 끝나면 `--continue`로 그 경계만 다시 맡긴다.
- **중단 후 진단**: 같은 오류가 반복되면 `$I`(관측 요약 줄)를 기록해 위임자에게 돌린다. 행 누적 실행이 20분을 넘으면 `dispatch-agent`가 `$D="[🏷] 사용자 대기"`를 기록하므로 자동 분석 검증자를 띄우지 않고 사용자에게 보고한다.

판단마다 사용자에게 한 줄로 알린다: `#<행> <경과>m — <계속 대기|방향 재지시|중단> : <근거 한 줄>`. 판단 없이 같은 대기를 다시 걸지 않는다(261031 위임자가 대행자 대기 중 10분 넘게 아무 판단·보고 없이 기다린 일이 두 번).
