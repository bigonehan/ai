# 점검 실패: exit 5 (사전점검)·exit 8 (제출점검)

## exit 5: 검증자 사전점검

`--role verifier` 시작 전에 `dispatch-agent`가 프로젝트 `.ai/docs/role-verifier.md`의 `# 사전점검` 절(`- <이름> : <셸 명령>`, exit 0 통과, 20초 제한)을 모두 실행한다. 하나라도 막히면 pane을 띄우지 않고 `exit=5 last=실패 — 사전점검: <이름>(<사유>); …`로 막힌 항목 전부를 한 줄로 낸다.

- 작업 도구·규칙 결함인 항목은 위임자가 직접 고쳐 다시 실행한다.
- 로그인·인증 등 전역 규칙 §1의 사용자 몫 항목만 한 줄로 모아 사용자 요청 한 번으로 묻는다.
- 감시 로그가 없어 시작이 거부되면 실제 런타임 로그를 `--watch-log`로 넘긴다. 파일 로그가 없고 검증자 출력으로 진행을 확인하는 프로젝트는 `.ai/docs/role-verifier.md`에 `watch-source: dispatch-log`를 단독 줄로 적는다. 빈 임시 파일을 감시 로그로 지정하지 않는다.

## exit 8: 제출점검

대행자가 제출해 `$H=검증`으로 끝나면 `dispatch-agent`가 프로젝트 `.ai/docs/role-delegator.md`의 `# 제출점검`(`- <이름> : <셸 명령>`, 개발용 적재 + 런타임 스모크, 항목당 120초)을 위임자 환경에서 실행한다. 실패하면 `$I`와 `$H=교정`을 기록하고 같은 codex 세션을 자동 재개한다(호출당 2회). 2회 넘게 실패하면 `exit=8 last=실패 — 제출점검: <이름>(<사유>) 재시도 2회 초과`로 끝난다.

- 진단(`$J`)으로 넘긴다. 위임자가 소스를 고치지 않는다.
- 데스크톱 앱처럼 대행자가 실행할 수 없는 런타임을 가진 프로젝트는 이 절을 둬서 버전 올리기·배포 전에 런타임 실패를 잡는다.
- 특정 기능 전용 점검은 `- <이름> [경로접두어,…] : <명령>`으로 범위를 준다. `dispatch-agent`가 행의 gate `ready`·`submit` 스냅샷 차이(검증자는 `--rows` 전체)와 겹칠 때만 실행하고, 변경 목록을 모르면 실행한다. 범위 없는 다른 기능 점검이 무관한 행을 막으면 막힌 행을 진단으로 넘기지 말고 그 항목에 범위를 준다(261112 #877이 Blender `place3d-assets`에 막힘).

## exit 5: 개선자 시작 조건·흐름 세션·누적 상한

- `exit=5 last=실패 — 흐름 세션 열림: …`은 이미 열린 흐름 세션(`flow.agent.session` 또는 `flow.verifier.session`)이 있는데 `--continue` 없이 새 세션을 띄우려 한 경우다. `--continue`를 붙여 이어 쓴다.
- `exit=5 last=실패 — 검증 재개 거부: …` 또는 `실패 — #<id> [🏷] 사용자 대기: …`는 대행자 재제출 없이 검증자만 재개했거나, 같은 실패 2회 반복·누적 20분 상한에 도달한 경우다. `next=agent-continue`면 대행자 `--continue`부터 하고, `next=user`면 추가 위임 없이 사용자에게 보고한다.
