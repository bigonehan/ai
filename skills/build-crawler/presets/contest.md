# 공모전 수집 프리셋

공모전 정보 수집(n8n `find_new_contest` 등)을 설계·구현·검증할 때 `../SKILL.md`와 함께 이 파일을 따른다. 이 파일이 공모전 수집의 필터·제목 정리 기준 원본이다.

## 1. 수집 필터링 (항목을 버리는 유일한 단계)

목적: 영상·AI 창작 **공모전**만 남기고, 공모전처럼 보이는 무관한 모집·행사를 버린다.

- 통과 조건(원래 제목 기준, 둘 다 필요):
  - 공모전 형태 낱말: 공모, 공모전, 콘테스트, 컨테스트, 챌린지, 어워드, 어워즈, 영화제, 페스티벌, 대회, 경진, 출품
  - 영상·AI 낱말: 영상, 동영상, UCC, 숏폼, 쇼츠, 숏츠, 미디어아트, 브이로그, 다큐, 시네마, 필름, 영화, 인공지능, 생성형, 영문 단독 AI(앞뒤가 영문자가 아닐 때, `AI디어`·`AI영상` 포함)
- 제외 조건(원래 제목에 하나라도 있으면 제외):
  - 교육·모집: 교육, 과정, 국비, 수강, 양성, 아카데미, 부트캠프, 교육생, 수강생, 기수 모집(`N기 모집`)
  - 참여·행사: 관람, 관람객, 참가팀 모집, 서포터즈, 체험단, 설명회, 해커톤
  - 이름 짓기: 네이밍, 명칭
  - 대상 제한: 청소년, 대학생
  - 사진 전용: 사진은 있고 영상 낱말이 없는 제목
- 마감일이 오늘(KST) 이전이면 제외한다.
- 예: `2026 AI 완도군 영상 공모전` 통과, `[대구가톨릭대학교] ROS2를 활용한 AI로보틱스 DREAM MASTER 4기` 제외(공모전 형태 낱말 없음), `MBC 기반 언리얼&블렌더 시네마틱 과정 2기 모집` 제외(과정), `무료 기업가정신 영화 DAY 관람객 모집` 제외(관람), `완주군 피지컬 AI 실증단지 명칭 공모` 제외(명칭).
- 같은 실행 안의 사이트 간 중복과 이미 저장된 행과의 중복도 이 단계에서 판정한다. 판정은 원래 제목·원본 링크·마감일로 하고 제목 정리 결과를 쓰지 않는다.
  - 이미 저장된 행과의 대조: 정규화한 원본 링크가 같거나, 마감일 차이 1일 이내이면서 저장된 정리 제목이 새 항목의 원래 제목 안에 그대로 들어 있으면 중복이다.
- 저장 뒤에 행을 지우는 단계는 두지 않는다. 버리는 판단은 저장 전에 끝낸다.

## 2. 라벨링·정리 (제목 줄이기, 항목을 버리지 않음)

목적: Grist에 기록할 제목을 고유명사만 남겨 짧게 만든다. 예: `2026 AI 완도군 영상 공모전` → `완도군`.

- 지우는 것: 연도(`2026`, `2026년`, `26년`), 회차(`제N회`), 일반 낱말(공모전, 공모, 콘테스트, 컨테스트, 챌린지, 대회, 어워드, 어워즈, 페스티벌, 영상, 동영상, 숏폼, 쇼츠, 숏츠, UCC, 미디어, 콘텐츠, 홍보, 사진, 창작, 제작, 생성형, 단독 낱말 AI), 빈 괄호·남는 구두점.
- 남기는 것: 지명·기관·기업·브랜드·고유 행사명. 다른 낱말에 붙은 AI(`AI디어`)는 고유명사 일부로 남긴다.
- 정리 결과가 2자 미만이면 연도만 지운 원래 제목을 쓴다.
- 이 단계의 낱말 목록은 1절 필터·중복 판정에 쓰지 않는다.

## 3. 정렬·범위

- 공모전에서 "최신 기록"(`../SKILL.md` 2절)은 마감이 얼마 남지 않은 것, 곧 마감 임박순이다. 모든 수집처를 마감일 오름차순(접수 중, 오늘 이후 마감)으로 받는다.
- 페이지형 수집처는 같은 페이지 수를 쓴다. 마감순을 지원하지 않는 수집처는 접수 중 전체를 받아 같은 필터로 거른다.

## 4. 검증

- 실제 실행 뒤 `[verify-step] loss-check`(원본 = 기록 + 제외 + 삭제, 삭제는 0)와 수집처별 `[verify-step] site-coverage`(사이트 마감순 목록의 통과 대상이 Grist API에 있는지)를 남긴다.
- 새로 기록된 행 중 1절 제외 조건에 걸리는 행이 0건인지, 기록된 제목이 2절 정리 결과(고유명사만)인지 함께 확인한다.
