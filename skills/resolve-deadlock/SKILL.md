# Resolve Deadlock

교착 행은 로그만 보고 끝내거나 실패로 닫지 않는다. 실제 실행으로 원인을 좁히고, 가장 근접한 해결책을 한 번 구현한다.

## 시작 조건

- `dispatch-agent`의 `last`에 `20분 초과`가 있거나, 메인 판단으로 대행자·검증자가 한 행에서 20분 넘게 막혔을 때 시작한다.
- 같은 날 다른 행, `완료`·`확인` 행, 새 요청에는 적용하지 않는다.

## 단계

| 단계 | 조건 | 수행자 | 할 일 |
|---|---|---|---|
| 1 | 교착 확인 | 1차 검증자 | 소스를 고치지 않고 실제로 재현·측정해 보고서를 쓴다 |
| 2 | 1차 확신도 `낮음`, 보고서 없음, 또는 1차 20분 초과 | 2차 검증자(새 세션) | 1차가 왜 못 밝혔는지 찾고 남은 가설을 실행으로 검증해 가장 근접한 해결책을 쓴다 |
| 3 | 형식을 갖춘 보고서가 있음 | 대행자 1회 | 보고서의 해결책을 구현한다. 메인이 배포하고 검증자가 흐름 테스트를 한다 |
| 4 | 2회 모두 보고서 없음, 또는 3단계 실패 | 메인 | 행을 닫지 않고 사용자에게 보고한다 |

## 메인

메인은 단계 전환과 `exit`·`last`·보고서 판정만 맡는다. 로그를 읽거나 직접 재현하지 않는다.

1. 1·2단계는 분석을 위임한다. `dispatch-agent`가 회차, 보고서 경로, 막힌 실행 로그, 이전 보고서 경로를 프롬프트에 붙인다.
   ```bash
   dispatch-agent --agent codex --role verifier --analysis --project <dir> --row <id> --prompt-file <F> [--watch-log <path>] --expect-seconds 540
   ```
   - 프롬프트에는 사용자 입력, 요구 결과, 관측한 증상만 쓴다. 원인을 미리 정하지 않는다.
   - `--analysis`는 감시 로그가 없어도 시작하고, `--resume`·`--rows`와 함께 쓸 수 없다. 행당 2회까지이며, 3회째는 `실패 — 분석 한도`로 거부된다.
2. 끝나면 보고서의 `# 확신도`만 읽어(`rg -n -A1 "^# 확신도" <보고서>`) 단계를 고른다.
3. 3단계 전에 보고서의 원인을 `$J`에, 수치 근거를 `$C`에 기록한다. 확신도가 `낮음`이면 `$J` 앞에 `[추정]`을 붙인다.
4. 대행자는 `--resume` 없이 새로 위임하고, 프롬프트에 보고서 경로와 `# 확인 방법`을 넣는다. 배포 뒤 검증자 프롬프트에는 `# 확인 방법`의 기대값 중 행 목표(`grist goal`)에 있는 것만 넣는다(보고서가 만든 절 이름·형식 기대를 넣으면 거짓 실패가 나고 1회 소진 뒤 되돌릴 수 없다, 261107 #717). 보고서가 쓰인 뒤 대행자 실행은 1회만 허용되며, 두 번째는 `실패 — 교착 구현 1회 소진`으로 거부된다.
5. 보고서 원인이 `dispatch-agent` 등 작업 도구 결함이면 전역 규칙대로 메인이 직접 고치고 원래 작업을 이어 간다. 로그인·결제 등 사용자 몫이면 4단계로 간다.

## 분석 검증자

- `role-verifier`의 금지 사항을 따른다. 제품 소스·테스트·버전을 고치지 않고, `$H`·`$I`·`$J`를 쓰지 않는다.
- 로그 확인으로 끝내지 않는다. 실패 경로를 실제로 실행하고 단계별 ms·횟수·관측 값을 잰다. `role-verifier`의 런타임 실행 줄이 이번 로그에 없으면 Stop hook이 막는다.
- 계측이 더 필요하면 소스 대신 프로젝트 `test/tmp/`의 임시 스크립트로 재고, 끝나면 지운다.
- 2차는 1차 보고서와 1차 로그를 먼저 읽고, 같은 확인을 반복하지 않는다. 1차가 놓친 경계와 남은 가설을 실행으로 판별한다.
- 원인을 확정하지 못해도 보고서를 쓴다. 가장 근접한 해결책과 그 확신도를 적는다.
- 프롬프트의 보고서 경로에 아래 형식으로 쓴다. 형식이 틀리면 Stop hook이 막고, 대행자 위임도 거부된다.
- 마지막 줄: `분석 — <행>: 확신도=<높음|중간|낮음> <원인 한 줄>`

```markdown
# 재현
<실행 명령·입력과 재현 횟수>

# 수치
<단계별 ms·횟수·관측 값. 숫자 필수>

# 배제한 가설
<가설 ⇒ 배제한 관측. 없으면 없음과 이유>

# 원인 후보
<가능성 높은 순서>

# 확신도
높음|중간|낮음

# 해결책
<수정할 경계와 내용>

# 확인 방법
<해결책이 맞는지 판별할 명령과 기대 값>
```

## 사용자 보고 (4단계)

`#<행> 교착 미해결 — <막힌 경계 한 줄>`, 시도한 분석·구현 횟수, 보고서 경로, 다음 선택지를 보고한다. `$H`는 `진단`으로 두고 `완료`·`확인`으로 바꾸지 않는다.
