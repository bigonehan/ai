# Improve Process

`task-complete` Stop은 `확인`된 행마다 changes `## 개선 요구`에 `- 처리 : [#<id>]` 줄이 없으면 종료를 막는다. 이 Skill이 그 줄을 남기는 유일한 절차다.

## 1. 개선 요구 기록 (작업 처리가 끝날 때마다)

- 흐름의 행이 확인되거나 과정·로그 결함·사용자 대기로 멈출 때 그 흐름에서 생긴 다음 항목을 행마다 한 줄씩 기록한다. changes를 손으로 고치지 않는다:
  ```bash
  ~/ai/scripts/bin/grist improve-note <id> --project <dir> --text '[실패 N회] <증상> — 원인: <경계> / 착각: <잘못 가정한 것>'
  ```
- 대상: 같은 행에서 2회 이상 실패한 오류(검증 실패·재위임·재배포), 구현·진단 중 착각한 점(틀린 추정 원인, 확인하지 않은 사전 조건, 잘못 고른 진입점, 규칙 위반).
- 해당 항목이 없으면 `--text '해당 없음 — 실패 1회 이하, 착각 없음'`을 기록한다.

## 2. 개선 (필수)

위임자는 행마다 하나를 고른다.
- 기록이 `해당 없음`뿐이면 위임자가 §3을 바로 기록한다.
- 실패·착각 줄이 있으면 개선을 맡기고 끝낸다: `dispatch-agent --agent codex --role improver --project <dir> --row <id> --prompt-file <F> --expect-seconds 540`(행이 `$H=진단`·`검증`·`확인`일 때 시작하며, 제품 결과는 통과하고 과정·로그 결함만 난 경우 대행자·검증자 재호출 없이 즉시 시작한다. 시작 기록이 있으면 `task-complete`가 메인 종료를 허용한다). 개선자가 끝날 때까지 위임자는 `~/ai`를 고치지 않는다. 작업을 막은 결함을 이미 고쳤어도 원인 분석과 다른 곳의 같은 결함 점검은 개선자에게 맡긴다.

개선자(또는 `해당 없음`이 아닌데 개선자를 쓸 수 없을 때의 위임자)는 아래 순서를 따른다.

1. 오늘 changes의 `## 개선 요구`를 `rg -n -A40 "^## 개선 요구" <changes>`로만 읽는다.
2. 항목마다 원인 위치를 고른다: 전역 규칙(`agent-rules`), Skill(`~/ai/skills/<name>`), hook·CLI(`~/ai/scripts/<crate>`: `main-edit-gate`·`task-complete`·`dispatch-agent`·`grist`·`win-smoke` 등), 프로젝트 `AGENTS.md`·`.ai/docs/role-*.md`.
3. 세 관점으로 판정한다:
   - 소모: 같은 탐색·위임·검증을 반복하게 한 지점(예: 사전 조건 미확인 상태의 검증자 위임, 메인의 반복 조사).
   - 병목: 사용자 대기·재시작·장시간 실행을 만든 지점(예: 검증 전 버전 올리기·배포 반복).
   - 환형대기: 두 절차가 서로의 결과를 기다려 진행이 멈춘 지점(예: 검증 기록이 행 단계를 요구하고 행 단계가 검증 기록을 요구).
4. 문구 추가보다 기계 강제를 우선한다(`manage-global-rules` §1). 기존 규칙이 있으면 hook·CLI 검사로 바꾸고, 작업 도구는 개선자가 직접 고쳐 실제 hook 환경(`env -i HOME=… PATH=/usr/bin:/bin`)에서 거부·통과를 확인한다. Skill·hook 생성 규칙은 `create-skill`을 따른다.
5. 개선이 필요 없으면 그 근거(이미 강제됨·일회성 환경 문제 등)를 한 줄로 남긴다.

## 3. 처리 기록

- 행마다 적용한 개선(또는 개선 불필요 근거)을 기록한다. 이 줄이 있어야 `task-complete`가 종료를 허용한다:
  ```bash
  ~/ai/scripts/bin/grist improve-done <id> --project <dir> --text '<바꾼 파일·명령> — <막는 대상>'
  ```
- 최종 보고에 `개선: <한 줄>`을 넣는다.
